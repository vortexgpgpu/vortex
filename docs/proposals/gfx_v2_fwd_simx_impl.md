# gfx_v2 — Fragment Work Distributor: SimX implementation plan

Implementation/sequencing plan for the §4 FWD from `docs/archives/proposals/
raster_sfu_interface_v2.md`. Design rationale lives there; this is the concrete
SimX build plan + ABI decisions. SimX-first, then RTL parity, then delete legacy.

## Why (recap)

The legacy RASTER↔SIMT handoff is **pull/poll/sentinel**: the host launches a
fragment-shader grid; each lane loops `vx_rast()` until the `pos_mask==0`
sentinel, reading per-quad `pid`/bcoords through CSRs. This violates the binding
doctrine (C2 single-issue, C3 scoreboarded handoff, C5 single-owner lifecycle)
and is the root of three observed defects:
- **SimX multi-cluster double-render** (fixed in 302eb580 by static tile→core
  ownership — the C4 half, kept here);
- **RTL `cores≥2` crash** — `VX_allocator.sv:66` double-release in
  `raster_mem.mem_scheduler` on heavy traces: multiple cores each drive the
  per-cluster producer's begin/fetch with no single owner (C5);
- **perf**: ~14 shader ops/quad + CSR-port pressure + the poll loop.

The FWD replaces it with **push/launch**: a single-owner producer pulls covered
quads from the unchanged TE/BE math, packs `NUM_THREADS` quads into a fragment
wave, and **launches** it onto the quads' owner core; the FS runs once per wave
over a pre-staged payload, then exits. An epoch FSM owns the draw boundary;
completion is `producer_drained ∧ launched==retired` (no sentinel).

## Machinery (verified in SimX)

- `Scheduler::activate_warp(wid, const cta_warp_record_t&)` (scheduler.cpp:99) —
  makes a warp runnable immediately (clears stall + stall_next). Precedent for
  HW-launched warps: RTU `CB_YIELD` injection (sfu_unit.cpp:330,
  `Scheduler::raise_async_trap`).
- `cta_warp_record_t` (cta_dispatcher.h:26) — PC/entry, tmask, thread_idx[3],
  mscratch (arg ptr), cta_id, lmem_addr. The FragmentDispatcher fills this like
  `CtaDispatcher::next_warp`.
- Per-lane regfile: `OpcUnit::warp_regs_t { ireg_file[reg][thread] }`
  (opc_unit.h:64) with `dtm_ireg(slot,reg,lane)` (opc_unit.h:55). slot =
  `(wid/ISSUE_WIDTH)/NUM_OPCS`.
- Completion: lane exit → `Scheduler::setTmask(wid,0)` → `active_warps_.reset` +
  `CtaDispatcher::warp_done(wid)` (scheduler.cpp:266 / cta_dispatcher.cpp:195).

## ABI decision — payload delivery

Target (doc C1, SOTA): per-lane **register window** seeded at launch, zero
shader loads. But the per-lane payload is ~14 words (pos_mask, pid, 3 axes × 4
corners of bcoords) — too many for the a0-a7 arg-register convention.

**FWD-1 lands the tractable form: per-lane LMEM payload + launch.** The FWD
writes each lane's `RasterStamp` to a deterministic per-(wid,lane) LMEM slot and
launches the FS wave; the FS reads its slot (no `vx_rast`, no bcoord CSRs, no
poll loop, no sentinel). This is still push/launch + single-owner epoch (fixes
C2/C3/C5 + the RTL crash root); the register-window (zero-load, C1) is a later
perf increment, not a correctness item. Trace-diffable against the RTL FWD.

Per-lane slot: `lmem_payload_base + (local_wave_slot * NUM_THREADS + lane) *
sizeof(frag_payload_t)`; `frag_payload_t = { u32 pos_mask; u32 pid; u32
bcoord[3][4]; }`.

## Epoch FSM (single owner — C5)

Per cluster, one owner (the producer). States: `QUIESCED → FILLING (producer
walking, may launch waves as quads accrue) → DRAINING (producer drained, waves
in flight) → QUIESCED` on `launched==retired`. `vx_rast_begin` (kept as the
draw-arm trigger; renamed semantics: "begin draw epoch") starts FILLING; the DCR
write boundary still re-arms. The host waits on epoch completion instead of the
kernel polling the sentinel.

## Host/runtime change — verified seam (no KMU surgery)

Grounding the dispatch path (`scheduler.cpp:146 schedule()` → `cta_dispatcher
.step()` → `activate_warp`; completion = `running() = active_warps ∨
cta_dispatcher running`, `warp_done` reclaims slots) showed a full push grid
generated by the FWD would otherwise need **KMU launch-completion surgery** (the
launch must end on `drained ∧ launched==retired`, not a fixed grid). Avoided via
the **driver-warp model**:

- Host launches `grid=num_cores` exactly as today — one **driver warp** per core.
- The driver warp calls a new blocking intrinsic `vx_fwd_run(fs_entry, arg)`
  (replaces the `vx_rast` poll loop): arms the per-core FWD with FS entry PC +
  arg + lmem payload base, then **suspends** (scheduler suspend/resume).
- The FWD **injects fragment-wave warps** at `fs_entry` into the core's free warp
  slots (driver holds 1; `NUM_WARPS-1` free), seeds each wave's per-lane
  `frag_payload_t` into its LMEM region, counts launched/retired.
- On per-core epoch complete (`producer_drained ∧ launched==retired`) the FWD
  **resumes** the driver warp, which returns and exits.
- **Completion unchanged** — the launch ends when all driver warps exit (existing
  path). No KMU/launch-ABI change in FWD-1.

Payload delivery is **LMEM** (over a register window: the ~14-word `frag_payload_t`
= pos_mask + pid + 3×4 bcoords exceeds the a0-a7/window budget). The wave-entry FS
reads its slot via `__local_mem()` + `threadIdx * sizeof(frag_payload_t)`. ABI
struct added to `sw/common/vx_gfx_abi.h`.

`vx_fwd_run` ISA: CUSTOM1 funct3=0 (the one free slot) or a funct7 sub-op of
funct3=3 (raster); legacy `vx_rast`/`vx_rast_begin` stay compiled in parallel
until FWD-2.

## FWD-1 core mechanism — FINALIZED (exact APIs)

Status: ISA foundation landed + compiling (frag_payload_t; vx_fwd_run intrinsic;
decode funct3=0; RasterType::FWD_RUN; doctrine classify; inert SFU handler).
Remaining core (the implementation), with the exact seams:

- **Same kernel entry, role-tagged.** Fragment warps reuse the driver's kernel
  entry PC (`cta_dispatcher` `cta_.PC` / `cur_kernel_pc_`) — NO separate-entry
  resolution. The FS kernel branches on an arg `role` field: `ROLE_DRIVER` →
  `vx_fwd_run(frag_ctx)`; `ROLE_FRAGMENT` → read payload + shade + vx_om4 + exit.
  Host sets up two arg structs; driver's mscratch=&driver_arg (role=driver,
  frag_ctx=&frag_arg), injected warps' mscratch=&frag_arg (role=fragment).
- **Arm + block (sfu_unit, RasterType::FWD_RUN).** Read rs1=frag_ctx; arm the
  per-core FWD; do NOT complete the SFU op — suspend the driver warp until the
  FWD signals epoch done, then complete (resume). Model on the async-op hold
  pattern already in sfu_unit (TEX/RTU keep the trace until rsp).
- **Injection.** Per-core FWD pulls a wave of ≤NUM_THREADS quads from the cluster
  `RasterCore` via the existing raster bus (reuse `serve_consumers` — one
  RasterRsp = one wave). For each non-empty wave: pick a free warp slot
  (`!active_warps.test(wid)`), build a `cta_warp_record_t` {PC=kernel entry,
  tmask=covered lanes, mscratch=frag_ctx, lmem_addr=per-warp payload region},
  `Scheduler::activate_warp(wid, rec)`, then seed the payload (next), launched++.
- **Payload seed = LMEM.** Add `LocalMem::write_word(local_addr, value)` (mirror
  of the existing `read_word`). FWD writes NUM_THREADS `frag_payload_t` to the
  warp's payload region: local offset = `lmem_addr - VX_MEM_LMEM_BASE_ADDR`.
  Per-warp payload region = a dedicated LMEM band (e.g. `top of LMEM - (wid+1)*
  NUM_THREADS*sizeof(frag_payload_t)`) that can't collide with the driver CTA
  slot or the FS's own LMEM (the wave-entry FS declares none). FS reads via
  `__local_mem()` (=`VX_CSR_CTA_LMEM_ADDR` = `cta_csrs.lmem_addr`) + `threadIdx`.
- **Epoch + completion.** FWD counts launched; `warp_done` on a fragment warp →
  retired++. When RasterCore drained (RasterRsp pos_mask=0 sentinel) AND
  launched==retired → resume the driver warp (its `vx_fwd_run` completes). Driver
  warp exits → host launch completes via the **existing** all-warps-exit path
  (no KMU change). FWD lives as a per-core child (alongside cta_dispatcher) or
  folded into the scheduler; it needs the core scheduler (activate/suspend/resume,
  active_warps, warp_done hook), the core `local_mem()`, and the cluster
  `raster_core()`.
- **Distinguishing fragment vs driver warp at warp_done** (for retired++): track
  a per-wid "is-fragment" bitset set at injection, cleared at exit.

## Increment plan

- **FWD-1**: implement the core above. New FS wave-entry kernel for `gfx_draw3d`.
  Validate **box** SimX multi-core byte-exact vs golden. Legacy `vx_rast` path
  stays compiled in parallel until FWD-2.
- **FWD-2**: full gfx suite (tex/om/draw3d, all traces) × multi-core ×
  multi-cluster × multi-drawcall byte-exact; retire the SimX `pos_mask` sentinel,
  bcoord CSRs, and `VX_raster_arb`.
- **FWD-3**: mirror the FWD 1:1 in `hw/rtl/raster/*` (producer + packer +
  launch + launched/retired counters), fixing the `cores≥2` allocator crash;
  rtlsim parity on the doctrine §4 matrix.
- **FWD-4**: delete legacy (`vx_rast`, bcoord CSRs, `VX_raster_arb`, the
  `raster_mem` fetch epicycle); update `vx_graphics.h`, mesa-vortex FS lowering,
  and the gfx kernels.
- **FWD-5** (perf, optional): register-window payload (zero shader loads, C1).

## Exit gate (master plan §6 P2)

box 2-drawcall + multi-core byte-exact vs SimX gold, on both SimX and rtlsim.
