Where the accelerators attach, and how each GEMM path uses them

Two figures over the existing Vortex hierarchy. The first places every module, shows the descriptor queue each engine submits into, and labels what each wire carries; the second maps the implemented cgo27_motivation modes onto those wires. Everything is read out of the current tree — port bindings from core.cpp, socket.cpp and cluster.cpp, cycle counts from a measured run.

FIG 1 Module placement, submit path, and wiring

Amber marks what this work adds. Each DTCU is drawn as its three real parts — descriptor queue → GEMM FSM → TMA — because a start instruction lands in the queue, not on the engine, and the TMA is what holds the memory ports.

  • 1The queue is where a start instruction actually lands. Dtcu::start() pushes a descriptor address and returns a ticket; if the engine is busy and the queue is full it returns 0 and stores nothing, so software must retry. Depth is 2 × NUM_CORES for the cluster engine and 2 × SOCKET_SIZE for a socket engine — each keyed to the set of cores that can reach it.
  • 2TMA is internal, not a peer module. DtcuTma is a plain helper owned by each Dtcu — not a SimObject, not shared. It is the half that owns the memory ports.
  • 3TCU is a core functional unit next to ALU/FPU/LSU/SFU, with its own dispatcher and a dedicated Local Memory port for the tile buffer. Its WMMA fragments arrive as ordinary LSU loads.
  • 4DXA is dispatched per core but lives at cluster scope: each core's SFU posts a descriptor, and the single DXA core reads GMEM through row 1 and writes into each core's Local Memory.
  • 5Row order is load-bearing. The socket engine's D rides row 0 as dcache write-through while its completion flag rides row 3, and priority is what keeps the flag behind its own data on the cross-socket path. A static_assert in cluster.cpp pins it.

FIG 2 How each cgo27_motivation mode flows

Eleven implemented modes, six distinct datapaths — modes 2, 5 and 6 share one and differ only in how many Local Memory buffers they pipeline across. Measured at three shapes, the largest sized so the GEMM fills every core in the cluster. SIMT only completes at the smallest — at Mode ids are grouped by what executes and are deliberately not dense; 3 and 4 once held the DTCU pair, now at 7 and 8, and were reused for the LSU-staged controls. 12 and 13 are the workgroup pair: the first modes whose CTA is wide enough for operand staging to amortise.
